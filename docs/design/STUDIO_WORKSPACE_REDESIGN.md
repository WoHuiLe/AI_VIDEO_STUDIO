# 动画制作工作台改造计划（讨论稿）

日期：2026-11-17。状态：供用户评审，未实施。承接 0.3.0；本轮不修改产品代码、项目数据或依赖。

## 目标与已对齐方向

用户提交文案，希望获得生动、统一、连贯的动画，观看后定位并修改局部。主界面以工具工作区呈现，制作过程中的分镜、提示词、素材绑定和技术选项按需打开。AI 用于值得创造和判断的环节，减少反复生成、搬运和不必要调用；不以消灭 AI 为目标。质量优先于制作技术的统一，整片美术方向先确定，再选择实现方式。

用户本轮选择“先保留浏览器，只改成工具布局”，随后要求复核 Web / Qt 取舍。建议继续本地 Web 工作台，桌面封装保留为后续选项。界面选型不会自动解决美术质量、模型接入、复杂人物动作或旁白同步问题。

## 载体取舍

| 路线 | 对本工程的收益 | 改造与风险 | 本轮建议 |
|---|---|---|---|
| 本机 Web 工作台 | 复用 Python 服务、已实现的本机文件操作、导出与已有网页能力；适合 Canvas/SVG 预览和属性面板 | 需重做状态管理、时间线和编辑器；浏览器快捷键及文件对话框有约束 | 采用 |
| Qt / PySide6 原生界面 | 可做原生菜单、停靠面板、文件对话框、独立窗口 | Python 领域逻辑可复用，但 Widgets/QML 编辑界面要重写；动画预览、视频编码、打包仍需另做 | 目前不迁移 |
| Web 编辑器加桌面容器 | 界面稳定后可嵌入独立窗口，保留 Web 技术；可接原生菜单与对话框 | 需单独验证浏览器运行时、媒体支持、进程生命周期、打包和安全接口，不是简单换图标 | 后续按需求验证 |

Qt 并非不能承载网页内容。若用 Qt WebEngine 嵌入 Web 编辑器，它属于第三条路线；不必为了独立窗口先重写为原生控件。暂不决定桌面容器，也不安装 Qt、Electron 或其他运行时。

## 产品与界面

默认深石墨灰主题，用层次灰区分背景、面板、输入区；单一低饱和强调色标识选中与主要操作，错误/警告独立。避免纯黑铺满、装饰性大标题、营销式首页与纵向表单。预留亮色主题，通过语义色变量实现；主题不改变导出画面颜色。控件使用清晰中文、可读字号和可见焦点，快捷键不劫持文字输入。

- 顶部菜单：文件、编辑、视图、画面、动画、导出、帮助。顶部工具栏只放当前项目、保存状态、撤销/重做、主要制作与导出动作。
- 左侧项目/素材面板：文案、镜头、角色与场景参考、图片与图层；可切换和折叠。音频模块后续按需加入，首版不占主工作区。
- 中央预览：占主要空间，支持播放、暂停、定位、缩放，明确展示草稿/已更新/待渲染。
- 下方镜头时间线：先实现镜头级选择、顺序、临时时长和播放头；旁白未对齐时明确标记，不能假称已同步。
- 右侧上下文属性：根据选中的项目、镜头或元素显示设置。“查看分镜/提示词”“替换素材”“重新设计”放入该面板及镜头快捷菜单。
- 底部状态栏：显示后台队列、进度、取消、失败原因和可恢复操作，不用模糊的“处理中”。

默认路径：新建/打开工程 → 提交文案与可选参考 → 确认整片视觉方向 → 完成首段/整片预览 → 暂停定位 → 修改当前镜头/元素 → 对比并接受 → 导出。外部 AI 复制任务与批量导入保留，作为可选制作方式；能力尚未接通时明确需要用户接续，不能画一个假自动生成按钮。

## 现有实现的去留

已核对：0.3.0 有真实的本机 Codex 分镜、外部 JSON 校验、整批任务、文件夹扫描导入、素材哈希保存、后台队列、图片/图层运镜、音频时间轴、增量渲染与交付打包。

- 继续复用：原文与素材保全、路径校验、任务与取消、FFmpeg/媒体检查、交接包、已有 Skill 与规则。
- 适配后复用：分镜策划、外部 AI 任务包、批量素材导入、图片/分层渲染。它们作为工作区中的命令和制作策略，不再主导页面结构。
- 前端重做：纵向提交页、作品详情大弹窗、逐项审核表单及依赖全量重绘的交互。先建立项目/选中对象/播放头/草稿等独立状态，避免轮询刷新覆盖编辑。
- 领域逻辑重做：目前 adopt 整份分镜会清空素材绑定。新增“局部镜头修订”和“全片重新设计”两条操作；局部修改必须保留无关镜头、素材和审核状态。
- 新增能力：持久化编辑修订、撤销/重做、前后版本比较、统一美术与角色/场景引用、预览与正式导出的共同时间采样约定。

## 动画与编辑模型

保留原始文案锚点、稳定镜头编号；分镜策划、视觉资产、场景元素、运动与剪辑时间分别存储并关联。镜头允许选择图片/分层、程序场景或导入视频，但整片沿用相同的美术与运动规范。模板是可复用制作零件，不允许将不同画风随意拼接。

工程需保存元素与动作参数，不能只留 MP4。每次编辑形成可追溯修订，记录影响范围；渲染缓存依赖当前修订及素材哈希，旧成品标记过期但保留。撤销恢复文档状态，不假装能撤回已经消耗的外部 AI 调用。导入旧项目时采用可回退迁移/适配，不直接覆盖原数据。

AI 的使用由镜头需要决定：文案理解和美术设计可集中使用；新人物姿态、新构图或细腻场景按需创作；已有角色、背景、物件尽量复用；运镜、视差、可控动作和光影可由程序执行。完整图内的物体不能自动视为可编辑图层，复杂动作不能用图片平移冒充。

## 分阶段实施与验收

| 阶段 | 工作 | 通过条件 |
|---|---|---|
| 1 视觉与交互验证 | 制作可点选工作区原型，用测试数据展示新建、预览、选镜头、属性与任务状态；确认深色视觉及面板布局 | 用户可看懂主要操作，常用动作无需在长页/弹窗之间往返；此阶段不把模型或导出模拟结果宣称真实 |
| 2 可编辑工程基础 | 镜头/元素/修订模型、修改命令、保存、撤销/重做、局部替换、旧项目适配 | 改一个镜头不重置其他镜头；保存重开可恢复；迁移失败原工程可用 |
| 3 端到端画面样片 | 用同一小段文案做统一美术关键画面与约 10–20 秒动画；验证 AI 与程序组合，不固定每镜头生图 | 用户认可连贯性与美术；暂停定位、局部改动、预览对比真实可用；正式导出与预览关键时刻一致 |
| 4 完整制作链 | 接回已有策划、外部 AI、批量导入、任务队列及导出；完善取消、重试、失败恢复和受影响渲染 | 从文案进入到导出可完成；等待外部素材明确可见；无重复提交或后台假进度 |
| 5 易用性与发布 | 主题、快捷键、窗口尺寸适配、长工程性能、操作指南与 changelog | 测试真实编辑/恢复/导出路径；媒体与私有项目不进 Git；确认后提交版本 |

阶段 1–3 是验证点；先证实布局和画面效果，再扩展完整制作功能。尚未完成性能测量，不承诺所有机器实时播放复杂场景或具体开发天数。

## 本轮范围

产出评审方案，不改网页、不安装依赖、不生成正式作品、不自动调用付费模型。暂不扩展为完整剪映替代品，不做任意多轨专业剪辑、复杂三维人物动画、自动口型或音频工作站。配音可先手工接续。

## 2026-11-17 补充对齐：画面优先与决策分工

### 本轮已确认

- 首版围绕文案到画面的创作与修改；浏览器内提供工具式布局。
- 用户确认首个样片采用“两类混合，按镜头表达需要取舍”：精细画面、运镜、景深与局部动作可与关键人物动作组合。不是所有镜头都要人物持续活动，也不能把整片图片平移当作动画质量通过。
- AI 不一律取消。统一叙事、美术和连续性优先，按镜头选择 AI 创作、已有素材复用和本地程序动画；无现成能力时明确接续方式。
- 配音当前不做，只预留后续接入边界；本轮不探测 VoiceStudio、不安装客户端、不生成声音。
- 用户授权助手决定大多数产品和技术细节；GrillMe 只用于影响结果、范围或资源约束的关键问题，不逐项询问控件、框架、颜色值和数据字段。

### 由助手负责的设计决定

1. 采用深石墨灰工作区与语义主题变量，给预览最大空间，面板可折叠；首版不做皮肤市场。
2. 以项目、镜头、素材、可编辑元素和修订组织工程；分镜与提示词属于当前镜头的高级信息。逐帧定位可用于检查，常规修改作用于镜头或元素的一段时间，避免只改一帧造成闪烁。
3. 首版菜单只服务视觉制作：文件含新建/打开/保存/导入；编辑含撤销/重做；视图含面板、主题、预览缩放；画面含风格参考、替换素材和按需 AI 任务；动画含动作、时长、镜头衔接；导出含预览片、正式视频和源素材包。已选对象决定可用命令，尚未实现的能力不放假按钮。
4. 创意设计先产出整片美术方向和少量关键画面，再扩展；在同一时间线内展示混合来源的镜头，沿用统一角色、场景、调色与运动规则。
5. 生成前给出制作安排及需外部接续的部分；失败不自动反复调用模型或扩大消耗。复用原项目并提供可回退修改，不直接清空现有分镜和绑定。
6. 首个样片选择一小段能同时验证氛围、局部运动和关键动作的文案；现有文案是可选测试素材，不把工程绑定到情感信件题材。真正制作前再确定样片材料，不在本轮擅自生成正式作品。

### 仅在必要时请用户决定

| 事项 | 什么时候问 | 当前状态 |
|---|---|---|
| 画面质量与动作验收 | 第一段样片的具体表现会影响路线时 | 已确认混合，逐镜头取舍 |
| 美术方向是否符合预期 | 有可观看的关键画面/短样片时，给具体结果判断 | 待样片阶段，不要求用户先写完整美术规范 |
| 新增费用、外部服务或资源需求 | 方案确实需要超出现有授权的调用或环境变更时，先说明收益和替代方案 | 本轮无新增；沿用不自动启用付费服务的约束 |

框架选择、组件划分、快捷键、布局细节、存储格式和测试由助手自行论证与决定。普通实现选择不成为确认关卡。

### VoiceStudio 后续接入方向

建议优先让现有 VoiceStudio 作为独立语音服务，通过适配层接入工作台；工作台负责提交文案、选择其已有音色、显示任务状态和接收生成音频，不再维护第二套语音模型环境。同时保留“在 VoiceStudio 手动生成后导入音频”的入口作为替代。

这是后续方向，不声称当前安装已支持或已验证接口。现有记录仅表明历史版本/音色情况，当前端口、协议、启动方式、长文本能力和取消语义均待到语音阶段只读核实。先不固定路径、端口或 API 名称，不操作其内部数据库、音色与模型。

当前只在设计中保留：旁白作为独立素材、片段与真实音频的关联、替换音频后的时间轴重校准。画面时长可暂定；之后接配音时允许调整镜头时长，不宣称无音频版本已实现口播同步。首版不新增配音面板、无效配置页、空占位按钮或完整混音轨道；已有旧项目音频数据继续保留。

## 0.4.0 实施记录 · 2026-11-17

已落地工具工作区、深/浅主题、项目资源、播放器、镜头时间线、上下文编辑、持久撤销/重做与静态版本对照；已接回原制作面板、批量导入和真实 FFmpeg 导出。新增独立 12 秒窗边程序示例，已在 1080p/24fps 完成编码、合成与打包。原有两个项目的八份核心清单经哈希核对未改变。

当前是可用编辑与渲染基线；阶段 3 的最终美术认可、更多题材场景、复杂人物动作、通用元素拖拽与任意曲线关键帧仍需后续验证与扩展。本轮不把内置窗边示例当作用户正式作品，也没有实现任意文案到任意画面的全自动创作。配音集成继续后置。
