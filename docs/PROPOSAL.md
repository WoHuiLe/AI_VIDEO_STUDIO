# AI Video Studio 总体方案

版本：评审草案 V0.1 · 2026-11-15

后续状态：用户已授权实现基础工具并检查。本文保留为方案基线，最新实现和未完成项见 `reports/IMPLEMENTATION.md`。

## 1. 要解决的问题

用户准备文案，希望 AI 将内容转化为生动、精致、连贯的视觉叙事，减少寻找画面、重复提示、素材整理和镜头制作的手工劳动。交付可以是图片、分层素材、独立动态镜头或无字幕粗剪；用户使用现有剪映 SVIP 继续精修。

成功标准不仅是程序能够输出 MP4，更是画面准确表达文案、角色和美术连续、镜头稳定自然、产物容易修改和接手，以及换一个 AI 后可以继续工作。

## 2. 范围和优先级

第一优先级：文案理解、视觉策划、分镜、美术与角色参考、图片质量。

第二优先级：可实现的图层运动、2.5D 视差、环境动态和独立镜头交付。

第三优先级：实际旁白对齐、无字幕粗剪、素材管理和重复操作工具。

辅助能力：VoiceStudio REST API、MCP、字幕和声音设计。它们不是视觉主线的前置条件。无法自动配音时，由用户手工生成或提供录音。

本工程保持轻量，不开发完整视频编辑器。首版不引入付费视频生成服务，不部署大型本地视频模型，不将 Colab 作为必需执行平台。以现有账号能力和本地工具为基础，额度不足时交接素材和任务说明，不自动转向计费 API。

## 3. 固定流程，保留创作空间

固定每一步的输入、职责、产物、质量检查和交接方式。根据项目选择画风、镜头数量和动态复杂度。绘本电影感是首个默认制作模板，非所有项目的强制风格。

文案先行有两条路径：

- 已有录音：核对文案和录音，按实际发音建立时间轴，再落实镜头节奏。
- 只有文案：先完成内容结构、分镜和画面设计；时间字段留空并标注未定。录音到位后调整节奏，需要时修改镜头。不得把估算时间描述为音频对齐结果。

提供四种交付范围，项目开始时选择：

| 范围 | 交付 | 后续由谁完成 |
|---|---|---|
| 图片包 | 分镜、参考图、合格图片、素材清单 | 用户进入剪映，或之后继续制作镜头 |
| 分层包 | 图片包及适合镜头的独立图层、补齐背景 | 用户或其他工具制作动画 |
| 镜头包 | 独立镜头视频、对应素材和运动说明 | 用户在剪映安排节奏、配音与转场 |
| 无字幕粗剪 | 镜头包、实际音轨、时间轴、粗剪及检查说明 | 用户精修、字幕、调色和最终导出 |

未要求的步骤不执行。缺少录音不阻止图片包和镜头包；镜头包可采用明确注明的临时时长，最终剪辑由用户调整。

## 4. 视觉制作方法

先分析文案的事实、想象、情绪和关键意象，再确定观众此刻应该看到什么。结合人物、环境、道具细节、主观视角和象征画面表达内容，避免字面配图和重复姿势。

先形成少量关键样张确认美术，再生产其余画面。使用统一角色参考、服装规则、色彩和光线设定；不能保证多轮生成天然一致，必须安排筛选和定向修改。

图像生成与图像编辑通过当次可用工具完成。工程保存可复用的提示、参考和结果，不假设 ChatGPT 网页端拥有稳定的无人值守批量接口。

动态按镜头选择：固定构图、单图运镜、分层视差、局部环境动态。重要内容优先保证源图与构图质量。分层需要可靠蒙版和遮挡区域补绘，不能仅用原图复制缩放。复杂人物动作可用动作前后镜头、细节和剪辑表达，不承诺真实行走、转身、口型或复杂互动动画。

光点、雨雪等独立元素较容易程序化；海浪、窗帘、翻纸等需按素材与方法验证，不能把效果名称当作已实现能力。

## 5. 跨工具的流程与 Skills

制作规范采用普通 Markdown、CSV 和 JSON，保存于项目中。Skill 是执行入口，规范和交接文件是共同依据。不同工具的技能安装方式另外适配，无法自动加载 Skill 时可以直接阅读同一文件。

首版采用一个总入口及六份阶段执行说明，避免同时维护多套重复规则。后续根据实际使用，再把某个阶段独立为可发现的 Skill，不提前强制拆成八个技能。

每个阶段说明包含：适用条件、输入、必要问题、执行步骤、输出、检查、返工、停止与交接条件。数据和文件负责保存事实与进度，不能只依靠聊天记忆。

## 6. 人机协作与控制点

默认只在重要创意节点合并审核：分镜及视觉方向、关键样张、动态预览。用户可授权连续执行；已有明确决定不反复询问。执行者自行完成尺寸、文件、引用等常规检查。

发现文案含义不清且会改变内容、关键人物表现不合适、工具缺失或额度不足时，记录具体问题并提出可选处理方式。不得自动购买服务、上传私人音色文件或修改用户软件配置。

## 7. 首版工程能力

工程将围绕项目初始化、素材编号、尺寸检查、分镜关联、局部重做、简单稳定渲染和交接整理逐步开发。具体代码与依赖须在后续阶段批准后决定。

不一开始搭建任务队列、数据库、网页后台或插件平台。优先让文件、模板和少量脚本支撑实际使用。源代码与素材分开，原始输入不可覆盖，失败记录不写成通过。

## 8. 评审建议

建议先确认以下默认取舍，而不是现在选择每一项技术版本：

1. 画面主线优先，语音 API 后置且可跳过。
2. 支持文案单独启动，以及四种交付范围。
3. 绘本电影感作为首个可更换的制作模板。
4. 先制作少量测试画面验证方法，再扩大代码和 Skills。
5. 首版使用文件交接，无后台和数据库。

以上为建议，尚未视为用户批准实施。没有阻碍形成方案的必答问题；具体项目的画幅、风格、角色参考及交付范围，在项目启动时按已有信息补齐。
