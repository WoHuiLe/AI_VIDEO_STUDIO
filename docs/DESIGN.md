# 工程与数据设计

状态：设计草案，不代表下列代码和目录已经实现。

## 1. 三层结构

制作规范层：普通 Markdown 描述方法和标准，独立于特定模型、聊天或插件。

项目资料层：原文、角色/风格、分镜、素材清单、任务状态和交接说明。通过稳定编号关联，允许不同执行者接续。

执行工具层：后续按需开发 Python/FFmpeg 辅助脚本；图像工具和语音工具可替换，网页端生成结果也可手工导入。执行工具实现规范中的部分工作，不能将工具成功响应等同于创作质量通过。

## 2. 未来目录职责

```text
docs/                  制作规范、环境和技术验证记录
planning/skills/        待评审技能草案；本次未安装启用
templates/             通用项目及交接模板
src/avstudio/          后续实际需要时才创建代码模块
tests/                 后续按真实代码风险补充测试
projects/<project>/    每个制作项目独立保存输入、策划、素材、工作文件和输出
library/               后续实际需要时保存公共角色、风格、已授权素材
```

建议项目内部结构：`input/`、`planning/`、`assets/`、`work/`、`output/`。原件只读保留，转换与渲染存入工作目录。大型素材不默认进入 Git；代码和文本规范可以版本管理。是否初始化 Git、采用何种依赖管理器留待环境盘点后决定。

## 3. 最小数据约定

| 数据 | 核心内容 | 关联 |
|---|---|---|
| 项目说明 | 交付范围、画幅、风格、录音状态、约束 | 项目 ID |
| 文案段落 | 原文引用、情绪、事实或想象、关键意象 | segment_id |
| 分镜 | 叙事目的、画面、景别、机位、运动、审核状态 | shot_id、segment_ids、asset_ids |
| 素材 | 路径、实际尺寸、来源、参考、采用状态、检查结果 | asset_id |
| 时间轴 | 实际音频、镜头起止、语音锚点、转场 | shot_id、segment_id |
| 交接记录 | 当前阶段、已确认决定、问题、下一步 | 项目 ID 和受影响编号 |

`segment_id`、`shot_id` 和 `asset_id` 不随文件排序变化。CSV 内多值先约定用分号分隔。时间用秒，未确定时留空；timeline_status 为 unset、provisional 或 aligned，只有依据实际录音核对后才能写 aligned。

评审状态：draft、needs_review、approved、rework；这是人或指定审核者对内容的决策。检查结果另用 PASS、FAIL、NOT_RUN、N/A，避免混淆“图片尺寸合格”和“用户认可美术”。

模板仅定义初步字段，不是已经实现的数据校验器。后续开发时应验证引用存在、时间范围合理、项目内路径不越界、必要字段完整。

## 4. 局部修改和可追溯

原文修改 → 标出受影响段落 → 复核关联镜头 → 只更新受影响图片、镜头和合成。实际录音变化则重新核对相关时间；依赖变化可能影响后续整段节奏，不能机械假定只有一个镜头变化。

前期先通过清单与记录管理依赖；验证确有重复需要后再开发自动失效和缓存。缓存可重建，正式源素材和可用输出不能自动清理。未来素材工具可记录 SHA256、生成参数与派生关系，本次不为大型旧视频重复计算或检查。

## 5. 工具与环境边界

- 工程 Python 独立于 VoiceStudio 内部 Python。版本由兼容性检查决定，不先锁死 3.11。
- FFmpeg 优先复用已存在且符合要求的版本；确有需要再独立安装，不覆盖现有软件或擅改系统 PATH。
- Pillow、NumPy、httpx 等按实际代码需要引入；不预装整份重依赖列表。
- VoiceStudio 作为可选外部服务，不操作其内部数据库、模型和既有音色。端口与接口均待验证。
- 剪映通过标准媒体、分镜和说明交接，不假定存在可用的公开工程导入 API，不修改私有草稿数据库。
- 不依赖 Colab；如某项独立处理确有收益，再讨论有限使用及数据转移范围。

## 6. 跨 AI 使用

同一 Skill 正文应可以直接作为指令文件阅读；工具特定配置放在单独适配说明中。Skills 的目录发现、参数和调用能力并不天然通用。

开始新会话时只需交接：总入口、当前项目说明、当前分镜/素材清单和交接记录。新执行者先读取这些文件，再按任务读取相关阶段说明。避免每次装入全部历史资料和重复研究工具。
